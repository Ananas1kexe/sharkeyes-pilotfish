# SharkEyes: руководство владельца

Для тебя как автора: как это работает, что в каждом файле, как менять и выпускать обновления, на чём зарабатывать.

---

## 1. Принцип работы в одной картинке

```
Пользователь ──► ТВОЙ backend (FastAPI) ──► LLM-провайдер (OpenAI/Anthropic/...)
                    │   ▲
        redact()    │   │  restore()
   "Иван, ivan@x.com" → "[NAME_1], [EMAIL_1]"   (провайдер видит только токены)
                    │
                  Vault (словарь токен ↔ значение, только в памяти, на время запроса)
```

1. **Redact (исходящее).** Перед отправкой текста модели детекторы ищут персональные данные и секреты. Каждое найденное значение заменяется на стабильный токен вида `[EMAIL_1]`. Реальное значение кладётся в `Vault`.
2. **Модель отвечает токенами.** Она пишет «отправлю на [EMAIL_1]», даже не зная адреса.
3. **Restore (входящее).** Ответ прогоняется через `Vault`, токены меняются обратно на реальные значения. Пользователь видит нормальный текст.
4. **Vault стирается** в конце запроса (`with shield.session()`). Ничего не пишется на диск и не уходит по сети.
5. **Injection-проверка** работает параллельно с шагом 1: если текст похож на «забудь все инструкции», запрос можно заблокировать ДО обращения к провайдеру.

Главное свойство продукта: **всё локально**. Нет сервера, нет БД, нет сети. Поэтому нет расходов на хостинг, и для клиента это аргумент по приватности: нам нечего красть или терять.

Ключевые решения:
- **Одно значение, один токен.** Если email встретился дважды, он везде `[EMAIL_1]`. Модель может рассуждать («это тот же адрес»).
- **Чек-суммы.** Теудат зеут: 9 цифр проходят проверку по алгоритму Израиля; карты проходят Luhn; IBAN проходит mod-97. Поэтому случайные числа не затираются, и ложных срабатываний мало.
- **Неизвестные токены не трогаются.** Если модель придумала `[EMAIL_9]`, которого нет в Vault, он остаётся как есть.
- **Стриминг.** Токен может прийти кусками (`"[EMA"` + `"IL_1]"`). Мы придерживаем только хвост, который ещё может стать токеном, остальное отдаём сразу.

## 2. Структура проекта и разбор каждого файла

```
sharkeyes/
├─ pyproject.toml            метаданные пакета, версия, зависимости
├─ README.md                 витрина на GitHub/PyPI
├─ MAINTAINING.md            этот файл
├─ sharkeyes/                сам пакет (то, что ставит pip)
│  ├─ __init__.py
│  ├─ detectors.py
│  ├─ vault.py
│  ├─ stream.py
│  ├─ injection.py
│  ├─ shield.py
│  └─ contrib_fastapi.py
├─ examples/
│  ├─ demo_app.py
│  └─ run_demo.py
└─ tests/
   ├─ test_core.py
   └─ test_fastapi.py
```

### `sharkeyes/detectors.py`: поиск данных (самый часто меняемый файл)
- `Match` ‒ найденный фрагмент: где начинается/кончается, тип (`kind`), значение, приоритет.
- `luhn_ok`, `israeli_id_ok`, `iban_ok` ‒ валидаторы по чек-суммам. Отсеивают случайные цифры.
- `Detector` ‒ базовый класс. `RegexDetector` ‒ универсальный детектор: регулярка + необязательный валидатор. `IbanDetector` ‒ особый случай (IBAN ловится «широко», потом обрезается до валидного).
- Блок `_SECRET`, `_IL_PHONE`, `_EN_NAME` и т.п. ‒ сами регулярки.
- `default_detectors()` ‒ **список всего, что ловится по умолчанию**. Тут добавляешь новое.
- `find_all()` ‒ запускает все детекторы и решает конфликты, когда два совпадения пересекаются: выигрывает больший приоритет, затем более длинное. Поэтому у секретов 100, у email 90, у имён 40.

### `sharkeyes/vault.py`: хранилище токенов
- `Vault.tokenize(kind, value)` ‒ выдаёт токен и запоминает. Перед сравнением значения нормализуются (`_norm`): email в нижний регистр, телефоны `+972-50…` и `050…` считаются одним номером.
- `Vault.restore(text)` ‒ возвращает значения на места по `TOKEN_RE`.
- `counts()` ‒ сколько значений какого типа, **без самих значений** (безопасно для логов).
- `clear()` ‒ стирание. `__repr__` не показывает содержимое.

### `sharkeyes/stream.py`: восстановление в потоке
- `StreamRestorer.feed(chunk)` ‒ принимает кусок, отдаёт всё, что уже безопасно показать. Если в конце буфера есть незакрытая `[`, держит её до следующего куска (максимум `MAX_TOKEN_LEN` символов).
- `flush()` ‒ в конце потока отдаёт остаток.
- `restore_iter` (синхронный) и `restore_aiter` (async) ‒ обёртки над ним.

### `sharkeyes/injection.py`: защита от prompt injection
- `_PATTERNS` ‒ список «сигналов»: имя, регулярка, вес (0-1). Есть en/he/ru.
- `scan_injection(text)` ‒ нормализует текст (убирает невидимые символы и огласовки иврита), прогоняет сигналы, считает итоговый балл как `1 − ∏(1 − вес)`. Несколько слабых сигналов складываются в сильный.
- Отчёт содержит только **названия сигналов**, а не цитаты, чтобы логи не засорялись данными пользователя.
- Это эвристика, а не гарантия. В README и на сайте так и сказано, держи эту честность.

### `sharkeyes/shield.py`: публичный API (то, чем пользуется клиент)
- `Shield(...)` ‒ настройки: набор детекторов, какие типы ловить (`kinds`), политика на injection (`"flag"` ‒ только записать, `"raise"` ‒ бросить `InjectionBlocked`), порог.
- `Shield.wrap(llm)` ‒ оборачивает его async-функцию вызова LLM одной строкой.
- `Session` ‒ состояние одного запроса: `redact`, `redact_messages` (работает со списком `messages` и многочастными сообщениями; injection проверяется только у ролей `user/tool/function`, чтобы твой собственный system-промпт не давал ложных тревог), `restore`, `restore_stream`, `summary`.
- `with shield.session()` ‒ гарантирует `vault.clear()` на выходе.

### `sharkeyes/contrib_fastapi.py`: интеграция
- `session_dependency(shield)` ‒ для `Depends(...)`: своя сессия на каждый запрос.
- `install(app)` ‒ превращает `InjectionBlocked` в аккуратный HTTP 400 (без данных пользователя в теле).
- Это единственный файл, который импортирует FastAPI. Так ядро остаётся без зависимостей. Для Flask/Django делается аналогичный `contrib_*.py`.

### `sharkeyes/__init__.py`
Что экспортируется наружу (`from sharkeyes import Shield`) и `__version__`. **Всё, что тут перечислено, ‒ твой публичный API: его ломать нельзя без повышения major-версии.**

### `examples/`
- `demo_app.py` ‒ мини-приложение FastAPI с поддельным «LLM», который запоминает, что ему прислали. Доказывает, что провайдер не видит данные.
- `run_demo.py` ‒ запускает 8 сценариев и печатает результат. Запуск: `python examples/run_demo.py`. Показывай это на демо клиентам.

### `tests/`
- `test_core.py` ‒ детекторы, чек-суммы, vault, стриминг при любой нарезке, injection, wrap, мульти-часть сообщений.
- `test_fastapi.py` ‒ сквозной тест: провайдер не видит данных, стриминг, HTTP 400 при атаке.
- **41 тест. Правило: ни одного изменения без прогона `pytest`.**

### `pyproject.toml`
Имя пакета, версия, `requires-python`, опциональные зависимости (`[fastapi]`, `[dev]`), настройки pytest. Версия указана здесь **и** в `__init__.py`; при релизе меняй оба места.

## 3. Как поддерживать: типовые задачи

**Установка окружения**
```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest
```

**Добавить новый тип данных (например, номер водительских прав)**
1. В `detectors.py` напиши регулярку и, если есть формула проверки, функцию `xxx_ok`.
2. Добавь строку в `default_detectors()` с подходящим приоритетом (выше = побеждает при пересечении).
3. Если нужна своя нормализация (чтобы «одно значение = один токен»), добавь ветку в `vault._norm`.
4. **Сначала тест**: в `tests/test_core.py` добавь пример, который должен ловиться, и пример, который НЕ должен (ложное срабатывание).
5. `pytest`, затем запись в CHANGELOG, версия +0.1.

**Добавить сигнал prompt injection**
Строка в `_PATTERNS` (имя, регулярка, вес) + тесты на «плохой» и на «безобидный» текст. Веса: 0.8 = явная атака, 0.3-0.5 = подозрительно, но возможно легально.

**Ложное срабатывание от клиента**
Попроси пример текста → добавь его в тест, который ожидает «не ловить» → ужесточи регулярку или добавь валидатор → прогон тестов. Клиент может и сам отключить тип: `Shield(kinds={"EMAIL", "PHONE"})`.

**Свой детектор у клиента (без правки твоего кода)**
```python
from sharkeyes import Shield, RegexDetector, default_detectors
shield = Shield(detectors=default_detectors() + [RegexDetector("ORDER", r"ORD-\d{8}", 55)])
```

**Новый фреймворк** ‒ новый файл `contrib_flask.py` и т.п., ядро не трогать.

## 4. Как выпускать обновления

**Версионирование (SemVer):** `MAJOR.MINOR.PATCH`
- PATCH (0.1.1): исправление ошибок, ужесточение регулярки.
- MINOR (0.2.0): новые детекторы/функции, всё старое работает.
- MAJOR (1.0.0): ломаешь публичный API (то, что в `__all__`).
Пока `0.x`, можно менять API, но предупреждай в CHANGELOG.

**Чек-лист релиза**
1. Ветка `main` зелёная (`pytest`).
2. Обнови версию в `pyproject.toml` и `__init__.py`.
3. Допиши `CHANGELOG.md` (что добавлено/исправлено/сломано).
4. Сборка и проверка:
   ```bash
   pip install build twine
   python -m build
   twine check dist/*
   ```
5. Пробная публикация на TestPyPI, потом настоящая: `twine upload dist/*` (нужен аккаунт и токен на pypi.org).
6. `git tag v0.2.0 && git push --tags`, релиз на GitHub с копией changelog.
7. Если сайт упоминает версию или фичи, обнови страницу.

**Автоматизация (бесплатно):** GitHub Actions. Один workflow гоняет `pytest` на Python 3.9-3.13 при каждом push; второй публикует на PyPI при создании тега (через «Trusted Publishing», пароли не нужны). Это тоже ноль серверов.

**Безопасность релизов:** включи 2FA на PyPI и GitHub, храни токены только в секретах репозитория, не коммить реальные данные в тесты (в тестах только выдуманные номера).

**Сопровождение сообщества:** `SECURITY.md` (куда писать об уязвимостях), шаблон issue с полем «пример текста (с выдуманными данными)», `CONTRIBUTING.md` с правилом «PR без теста не принимается».

**Чего пока нет, но стоит добавить до публикации:** файл `LICENSE` (см. ниже), `CHANGELOG.md`, GitHub Actions, проверка, что имя `sharkeyes` свободно на PyPI и не занято чужой торговой маркой.

## 5. Бизнес-модель

### Важное про лицензию (сейчас в `pyproject.toml` стоит MIT)
Ты хотел, чтобы коммерческие компании не могли использовать бесплатно. **MIT этого не делает**: MIT разрешает всё, включая коммерческое использование и перепродажу. Выбери до первого релиза (после публикации под MIT забрать права назад нельзя для уже выданных версий):

| Вариант | Что даёт | Минус |
|---|---|---|
| **MIT/Apache** + платный Pro | максимум распространения, доверие | коммерческие компании не платят за ядро; деньги только с Pro и услуг |
| **AGPL-3.0 + коммерческая лицензия** (двойная) | это настоящий open source; компании, не желающие открывать свой код, покупают у тебя исключение | AGPL пугает юристов многих корпораций, кому-то это плюс (покупают лицензию) |
| **FSL / BSL** (source-available) | исходники открыты, конкурентное коммерческое использование запрещено на 2 года, потом переходит в Apache/MIT | формально это НЕ open source (не одобрено OSI); нельзя называть «open source» без оговорки |

Для одного разработчика без серверов обычно разумнее всего: **ядро под AGPL (или FSL) + коммерческая лицензия**, либо **MIT-ядро + платный Pro-пакет**. Выбор лицензии согласуй с адвокатом, я не юрист.

### Где деньги (всё без своих серверов)
1. **Коммерческая лицензия** (если выбрал AGPL/FSL): фиксированная цена в год за компанию, например $299-$1 500 по размеру.
2. **Pro-пакет** ‒ закрытый пакет, который ставится рядом: дополнительные детекторы (национальные ID разных стран, медицинские коды, адреса), корпоративные правила, отчёты для аудита, обновления паттернов injection. Проверка лицензии **офлайн**: ключ подписан твоим приватным ключом (Ed25519), пакет проверяет подпись публичным. Сервер не нужен, пользователь не «звонит домой» (это ещё и аргумент по приватности).
3. **Услуги**: внедрение, настройка под их данные, аудит приложения, обучение. На старте это основной доход и самая быстрая валидация.
4. **Поддержка с SLA** для компаний (чат/почта, срок ответа).
5. **Гранты**: Israel Innovation Authority, программы поддержки open source и кибербезопасности. Подходит как раз под «privacy-first, локально, open source».
6. **Спонсорство** (GitHub Sponsors) ‒ небольшой, но стабильный довесок.

### Кто клиент
Небольшие и средние компании (в том числе израильские), которые строят чат-ботов/копилотов на LLM и работают с персональными данными (медицина, финансы, юристы, HR, госзаказчики). Для них аргумент: «данные не уходят провайдеру, соответствует требованиям закона о защите приватности (Amendment 13), GDPR, и ты можешь это доказать тестами».

### Дорожная карта денег
1. **0-1 мес.**: выбрать лицензию, добавить LICENSE/CHANGELOG/CI, опубликовать на PyPI и GitHub, выложить сайт.
2. **1-3 мес.**: 10 разговоров с реальными командами, использующими LLM; сделать 1-2 бесплатных пилота в обмен на отзыв. Улучшать детекторы по их реальным данным.
3. **3-6 мес.**: платный Pro-пакет и первые услуги. Цель ‒ первые 3-5 платящих клиентов.
4. **6-12 мес.**: подать заявку на грант, расширять языки и страны.

### Юридическое и налоговое в Израиле (кратко, проверь у бухгалтера)
- Регистрация: «осек патур/мурше» на старте (проще и дешевле), позже «хевра беам» при росте и привлечении клиентов-корпораций.
- Договор для клиента: ограничение ответственности (инструмент снижает риск, но не гарантирует 100% защиту).
- Торговая марка: проверить имя SharkEyes в реестре Израиля и в международных базах до активного продвижения.
- Мировой рынок: платежи через Stripe/Paddle/Lemon Squeezy (Paddle и подобные берут на себя налог с продаж).

### Риски и честность
- Регулярки не ловят всё. Не обещай «100% защиту» ни на сайте, ни в договоре.
- Конкуренция: Microsoft Presidio (open source, бесплатный), облачные DLP-сервисы. Твоё отличие: иврит и израильские форматы, нулевые зависимости, один файл для вставки, стриминг, ноль серверов.
- Главный риск не код, а продажи: без первых клиентов проект останется хобби. Поэтому раздел «Дорожная карта» начинается с разговоров, а не с кода.

## 6. Шпаргалка команд

```bash
pytest                          # все тесты
pytest -k stream -x             # только стриминг, остановка на первой ошибке
python examples/run_demo.py     # демо в консоли
uvicorn examples.demo_app:app --reload   # демо-сервер (swagger на /docs)
python -m build && twine check dist/*    # собрать и проверить пакет
```
